# Consultation

Use this reference in Ask when deciding whether work is worth adding, how to organize it, or where information belongs. Weekly review may use the same method while retaining its own inventory and commitment rules. Keep advice in chat; use Plan for concrete proposed edits and Apply for explicitly requested writes.

## Ground the decision

Restate the decision the user is trying to make. Recover settled inputs and inspect the named objects plus existing records that could overlap or change the recommendation under [Working context](working-context.md). For a new idea, locate likely owning context before proposing a new object. If access is unavailable, reason from attributed user input and identify what remains uninspected; do not claim that no duplicate exists.

## Assess relevant dimensions

Use only dimensions that could change the answer. These are reasoning prompts, not a mandatory interview or response template.

| Dimension | Assessment |
| --- | --- |
| Purpose | Desired outcome, problem addressed, why now and what would count as enough. Consider deferring or reusing existing work when a new object adds little value. |
| Placement | Existing owner, overlapping outcomes and primary scope home. Discuss a separate Project when the work has an independently managed purpose; otherwise consider an existing Milestone or Task. Apply [Project](project.md) and [Milestone](milestone.md), not title similarity alone. |
| Granularity | Separate outcomes, scheduling, dependencies or review decisions that justify splitting. Use [Task](task.md) for checklist versus Task and [Milestone](milestone.md) for substantial work packages. Task count alone does not measure workload. |
| Feasibility | Readiness, real prerequisites, focused effort range, waiting time and available capacity. Label estimates and assumptions. Ask how much time or attention the result deserves; shrink scope or defer work when it exceeds that budget. Consider what existing work would have to wait. |
| Information | Authored Resource versus external Reference, canonical source, intended reader and use. Follow [Resources](resources.md) for status and placement and [Research](research.md) for scientific files. A short contextual note may fit an existing page or log; create a separate Resource only when it has a distinct use. |

For file placement, inspect the owning workspace's conventions and nearby structure before recommending a path. Distinguish scientific source files from Notion management summaries. Link canonical information rather than copy it across catalogues, notes and Tasks.

For merge proposals, compare purpose, completion criteria, lifecycle, ownership and dependencies. Explain what identity, links or history must survive; a recommendation to merge is not permission to delete. Prefer referencing shared outputs when distinct work packages still need separate control.

## Discuss with little friction

Lead with a provisional recommendation and its reason. Offer two or three materially different options when there is a real tradeoff; a simple decision can have one recommendation. State important uncertainty and ask one focused question at a time when its answer could change the choice. Reuse facts and owner confirmations already given. Avoid repeating settled decisions or filling missing priorities, deadlines or capacity with guesses.

Stop probing when the choice has enough support. Carry forward the selected direction, reason, relevant objects, remaining unknowns and recommended next step. An idea remains a candidate until the user selects it. The user's interest in next week's work does not itself establish a weekly commitment.

## Work with the other workflows

- Ask owns open-ended consultation, including future work outside a weekly review.
- Weekly review owns the past-week inventory, outcome reconciliation and next-week commitment under [Weekly focus](weekly-focus.md). Use consultation inside it when candidates need discussion; keep that context rather than requiring another invocation.
- Plan owns the exact target records, draft content, relations and effects once a direction is selected. Return to discussion only for material unresolved choices.
- Capture and Apply retain their existing write scopes. Consultation alone changes no records, files, priorities or calendar events.

## Example

The owner says a viewer is nearly ready for one research project and may serve later projects. Inspect its present purpose and ownership. Compare a supporting Task in the current Project with a separate tool Project linked from the research context. Ask whether the intended outcome is a usable version for this experiment or ongoing independent tool development. Keep that choice open until answered; do not infer a new Project solely from reuse potential.
