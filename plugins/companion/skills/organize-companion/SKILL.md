# Organize Companion

Read [shared definitions](../../shared/README.md), [Working context](../../shared/references/working-context.md) and [Resources](../../shared/references/resources.md).
Read the named Project and its current direction first. Resolve the project by identity. If no project is named, start with the named note and find its owner.

## Inventory

Inspect the live Notes and Resources schemas. Enumerate all project-linked records, including custom Archived status, and follow every result page. Inspect milestone-linked records, explicit page links and project catalogues that can reveal missing ownership. Use search to find candidates, not to establish a complete inventory. Keep unrelated projects outside scope.
Report linked inventory separately from unassigned candidates. Check fetch truncation and unsupported blocks. Retrieve accessible missing content before concluding. Record material gaps when complete retrieval is unavailable.
Read the complete bodies of every proposed restructuring, merge or move target. Compare their sources, purpose, lifecycle and affected links. Read related records where they could change the proposed destination. Summaries and headings alone cannot establish duplication.

## Diagnose

Separate project workspaces, authored reusable guidance, external References, dated logs, drafts and historical snapshots by their actual use. Keep the existing shared definitions as the authority for Resource types and placement.
Identify misleading views, competing canonical sources, repeated sections, stale current-state pointers, unclear ownership and empty placeholders. Cite the exact page or view and the observed evidence for each finding. A similar title is only a candidate overlap.
Distinguish current owner statements from historical content. Flag conflicting versions without choosing the newest number automatically. Management archive status does not establish scientific retirement.

## Propose

Prefer navigation, labels and a short opening before splitting pages or changing databases. Keep one canonical home for each purpose. Reference shared material rather than copying it.
For each target, propose keep, rename, restructure, link, move or merge. Specify exact destination, content boundaries, related effects, and what identity, links and history survive. Preserve snapshots and unique content. A merge proposal is not permission to delete.
Show one representative opening: purpose, dated current state, where to work, canonical sources and history. Adapt the sections to the material rather than forcing every note into a template.
Inspect the actual filters and sorts before recommending a view change. Separate project-local views from shared database changes that affect other projects.

## Handoff

Use [Plan Companion](../plan-companion/SKILL.md) to render a retrievable HTML proposal with the [plan artifact contract](../../shared/references/plan-artifacts.md). Include coverage, concrete changes, preserved material, unresolved decisions and source links.
Keep Notion read-only. Creating a local plan does not authorize applying it. On an explicit Apply request, hand the selected plan ID and revision to [Apply Companion](../apply-companion/SKILL.md). Refresh targets before writing.
Route external defect audits through the installed audit workflow only when requested and authorized. Keep private content local unless the user authorizes the external destination. A rejected export remains blocked; it does not prevent a clearly labelled local organization review.
