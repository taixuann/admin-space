# Calendar Companion

Read [source ownership](../../shared/references.md#source-ownership-and-reads), [Calendar and Rhythm rules](../../shared/references.md#calendar-and-rhythm), and the [current approved Calendar control specification](https://www.notion.so/3fd0a859ed1f81eeb5dcc8d4d2aeaa78). Use its operational revision, which supersedes historical draft text. The linked attachment with connector recipes was inaccessible when this skill was drafted. Retrieve it before relying on recipes not stated in the shared policy.

Resolve the requested week and scope. In routine work, inspect only Research, Development and Study calendars. Inspect other calendars only when the user requests cross-calendar conflict protection. Fetch current events and relevant Notion, Linear, GitHub/Wiki and Drive/Rhythm records. Follow pagination and report gaps. Assume connected sources are current; do not run routine sync audits.

Match records by verified identity and context, not title similarity. For Research, use Notion Goals, Projects, Milestones, Tasks, status, priority, due date and blockers. For Development, use Linear projects and issues; keep focus at project level if no issue is ready. For Study, use the published topic index, branch goal and substantive recent evidence; do not use theme-only changes or commit counts as progress. Use Rhythm only for capacity and area mapping, never as evidence of completion.

Before a change, inspect event ID, calendar, start/end, timezone, recurrence, reminders, attendees, description, links and status. The owner-approved small edits are clear spelling, grammar, capitalization, stray punctuation, unambiguous canonical links, clear domain placement and the verified Research transition from Not Started to In Progress. Never reopen Complete or Archived work or mark work complete because an event ended. Do not move fixed commitments, invent durations, or turn placeholders into guessed tasks. Preserve all unrelated fields.

Perform only explicitly authorized scheduling or repairs, plus the standing small corrections above. Update the existing event where applicable, then re-read it. Report changed, unchanged, unresolved and coverage. Do not promise ongoing monitoring or sync.
