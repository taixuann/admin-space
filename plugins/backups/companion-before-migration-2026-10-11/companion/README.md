# Companion shared definitions

The active skills are [ask-companion](../ask-companion/SKILL.md), [plan-companion](../plan-companion/SKILL.md), [apply-companion](../apply-companion/SKILL.md), [capture-companion](../capture-companion/SKILL.md), and [weekly-review-companion](../weekly-review-companion/SKILL.md). This directory contains shared definitions, not an executable skill.

Read only the references relevant to the selected project and question:

Read [Working context](references/working-context.md) for object discovery, focused questions, workflow handoffs and readiness to apply.
Use its [Coverage and effects](references/working-context.md#coverage-and-effects) table to distinguish each skill's read scope, output and write scope. Plan and Apply serve all supported object types; Weekly review owns the full Project inventory and weekly selection.

- [Consultation](references/consultation.md): purpose, placement, granularity, workload and focused discussion before concrete planning.
- [Project](references/project.md): required fields and project information.
- [Milestone](references/milestone.md): scope, outcomes, timing and dependencies.
- [Task](references/task.md): ownership, deadlines, granularity and dependencies.
- [Weekly focus](references/weekly-focus.md): priorities, selection and historical logs.
- [Resources](references/resources.md): types, placement and catalogue rules.
- [Research](references/research.md): local progression, evidence and GitHub links.
- [Capture and evidence](references/capture.md): canonical logs, pending attention and Evidence map navigation.
- [Review cases](references/review-cases.md): workflow boundary and missing-information cases to check when changing the suite.

Use the installed `simple-english` skill in Plain mode for English descriptions, overviews and status summaries. Preserve source facts, technical names, uncertainty and completion boundaries. Keep writing rules in that skill.
For Notion Overviews, follow the accepted list and bold-label layout in [Project](references/project.md#overview-presentation). This presentation preference takes precedence over generic restrictions on bold lead-ins in the writing skill.

Notion owns project management records. Local research records own scientific evidence. GitHub can expose published source versions. Use the existing connectors and scoped local instructions. Connector access does not authorize writes.

Keep reusable definitions here. Keep project-specific facts, targets and history in their owning records. Update definitions only when the user requests or accepts a persistent change.
