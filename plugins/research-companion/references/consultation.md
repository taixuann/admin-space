# Research consultation

## Ground the question

Start from the named object and read its owning Project context. For a Study, inspect its question, input selection, methods and interpretation limits. Read selected run locks or results only when the advice depends on them. For Goal or Story advice, inspect materially affected relations. Report missing, historical or conflicting sources. A stored claim is not a fresh verification, and file existence is not scientific acceptance.

Keep the discussion proportional to the question. A descriptive overlay needs
clear inputs, groups, outputs and limits. Mechanism or inference questions need
the relevant alternatives, discriminating evidence and method decisions.

## Active scientific skills

An active skill supplies an on-demand reasoning procedure inside consultation.
It does not gain ownership of Study or Research Progress records.

- If the research direction is open, read
  [scientific brainstorming](../skills/brainstorming/SKILL.md). Use its map,
  candidate generation and shortlist procedure. Return the shortlist to the
  scientist; a shortlist does not select the direction.
- If the question is fixed, refine it within its accepted scope. Do not run
  broad direction generation or reopen settled decisions merely to use brainstorming.
- If competing explanations need testable predictions, read
  [hypotheses](../external-skills/hypotheses/SKILL.md).
- If an actual experimental design decision is unresolved, read
  [experimental design](../external-skills/experimental-design/SKILL.md).
- If a factual gap could change the recommendation, use the existing scientific
  lookup guidance and a verified available provider. For literature consultation
  in this pilot, read the installed `hyperresearch` skill before using it.
  Start with Level 0 notes. Use Level 1 for a bounded gap that notes do not answer.
  Read the returned source before citing it. Level 3 requires explicit opt-in.
  HyperResearch supplies evidence, not scientific decisions or Study state.
  Existing Study INIT source-order and ownership rules still apply.

For each proposed consultation action, state the question, reason, capability,
expected evidence and decision it informs. Label it proposed or completed.
An unperformed lookup is a proposed action, not a cited finding.
Use an available read-only interface for notes. CLI index writes or fetched
vault notes require the external workspace's permissions and owning instructions.
Keep lookup scope proportional to the unresolved question.

Read related studies when they answer a specific need. State their transfer limits.
A descriptive study does not need to settle every mechanism or confound.
It must keep causal claims outside scope and retain necessary provenance checks.

Consultation performs no scientific computations. A requested exploratory
analysis is a separate authorized task under the applicable owning instructions.
Read raw evidence in place. Preserve raw bytes and historical runs.

## Prepare the handoff

Carry forward what the scientist supplied or accepted. Label proposed methods,
thresholds, exclusions and interpretations as proposals until settled.
Use the current Study INIT reference for exact admission and output rules.
For explicitly selected new plan-led analyses, Plan Research settles the analysis
contract and Implement Research owns authorized implementation and execution.
Study INIT rules remain specific to Study-owned leaves.
Keep the handoff in chat unless the user requests a saved proposal.
An explicit request for an action authorizes only that action's scope.

For an old Study, distinguish consultation from migration and re-analysis.
Inspect compatibility instructions before proposing either operation.
Preserve the original source identity and history. New scientific questions
or methods need an explicitly agreed follow-up scope.
