# Research context

Resolve the selected local project's path and scoped instructions. Start with its actual progression entrypoint; in research-projects this may be `progress/progression.md`, not a folder literally named `progression/`. Follow relevant Goals and Stories, then selected Study reports, results and run records when evidence is needed. Read only sources relevant to the discussion.

Treat progression summaries as navigation. Compare them with detailed records before stating completion. Distinguish historical study completion, unfinished synthesis, new instrument/software development, and scientific acceptance. Attribute user updates separately from inspected artifacts and surface conflicts without silently changing either source.

Keep research evidence in its owning local project. Use the Notion Description for purpose and intended outcome; use an Overview tab for context and Current direction. Use an Evidence map tab for source navigation, a comparison date, and any material unresolved discrepancy. Avoid copying full progression tables, run histories or scientific results into a second maintained record.

Refresh the Evidence map from local sources when requested. Do not claim automatic synchronization without an implemented and verified mechanism. Prefer direct GitHub file links when the repository is known. Inspect the repository branch and remote file before linking. Use ordinary external links in Notion, not native page mentions for GitHub files. State when local and remote contents differ. Branch links navigate current files; commit links preserve an exact reviewed version. Neither updates the Notion summary automatically. Keep local-only paths as source locators. Notion synced blocks alone do not synchronize local files.

Write Purpose as the concrete question and intended outcome. Summarize Current direction through relevant milestones or substantial work packages: current state, available result, and next step or unresolved limit. Reuse existing milestone identities when available. Label local research Goals as source work packages rather than silently converting them into Notion Milestones. Attribute completion to its source and keep new development separate from earlier results. Do not create milestone records from an overview-writing request.

Do not add Milestone or Task tabs to this research information layout by default. Existing work records and relations remain separate; omitting a tab is not permission to delete records or database blocks. Add a Catalogue only after its purpose and contents are agreed.

Companion owns consultation and scoped requested Notion edits. Follow the research owner's workflows for scientific execution, interpretation, acceptance or persistent local-state changes.
