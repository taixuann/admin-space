# Companion review cases

Use these cases when reviewing workflow changes. This is a manual contract checklist, not evidence of model performance.

| Case | Required behavior | Owning rule |
| --- | --- | --- |
| Ask about one Task whose dependency is blocked | Read the owner and prerequisite; advise with the blocker; leave records unchanged | Working context: Coverage and effects |
| New tool might support several research Projects | Inspect current purpose and owner; compare existing scope with an independent Project; ask the deciding question without creating records | Consultation: Ground the decision; Example |
| User proposes ten Tasks for next week with unknown capacity | Assess outputs, effort and prerequisites rather than Task count; keep candidates separate from commitment | Consultation: Assess relevant dimensions; Weekly focus |
| Two Milestones have similar names | Compare outcomes and dependencies; recommend merge or shared-output references with history and link effects; leave records unchanged | Consultation: Assess relevant dimensions |
| User asks where a study file or meeting note belongs | Inspect owning conventions; distinguish scientific source from management note; recommend canonical placement without duplicating or writing | Consultation: Assess relevant dimensions |
| Weekly review discovers an idea needing discussion | Use consultation in the review, preserve inventory and settled inputs, then propose a bounded commitment | Consultation: Work with the other workflows |
| Ask discussion settles several Tasks for next week | Present Plan, account for every candidate, propose weekly deadlines, leave daily scheduling to the user, wait for explicit Apply | Ask Companion; Weekly focus |
| Apply finishes with conditional or unresolved candidates | Verify actual writes and identify remaining decisions; preserve prior confirmations and avoid extra writes | Apply Companion |
| User reports one weekly outcome and omits other work | Inventory the whole selected Project, paginate, reconcile Project and Milestone membership | Weekly focus: Inventory and identify the week |
| A Task is due this week but has no activity history | Include it as due; leave execution and completion unproven | Weekly focus: Inventory and identify the week |
| Current priority differs from last week's selection | Recover dated history or report unknown historical priority | Weekly focus: Inventory and identify the week |
| Urgent Task belongs to a Priority 4 Milestone | Surface the conflict; settle priority before the new commitment; preserve backlog | Weekly focus: Priority eligibility |
| Priority 1 Milestone contains a Priority 4 Task | Keep that Task outside the commitment; select a feasible eligible subset | Weekly focus: Priority eligibility |
| Inventory is truncated or a database is inaccessible | Report partial coverage; retain unknowns; proceed only with supported conclusions | Working context: Coverage and effects |
| Plan moves a Task to another Milestone or Project | Inspect both owners, dependencies and commitments; identify every included relation change | Working context: Coverage and effects |
| Owner says a named Task is done but Status is Not Started | Accept owner-confirmed completion; propose Complete without demanding proof or repeated confirmation; write only on request | Working context: Owner progress and recorded state |
| Owner says a Milestone is nearly done or only its basic work is done | Keep it open; identify the remaining scope and propose only supported Task changes | Working context: Owner progress and recorded state |
| Owner clearly confirms a Milestone done with stale open children | Accept the confirmation; propose child disposition and dependency reconciliation without cascading writes | Working context: Owner progress and recorded state |
| Capture says work is complete | Save attributed information; property changes require their own requested scope | Capture Companion |
| Apply is interrupted after a template or entry write | Fetch actual state before retry; avoid duplicate template or log content | Resources: Templates and creation; Apply Companion |
| Apply completes only part of several requested changes | Read back each write and report applied, failed and remaining changes | Apply Companion |
| A log correction has a pending pointer or weekly summary | Trace the references; preserve dated history; change only requested destinations | Working context: Coverage and effects; Capture and evidence |
| Resource promotion lacks an Area or uses the wrong Project | Resolve actual destination relations before promotion or assignment | Resources: Status and placement; Relations and hierarchy |
| Several Projects share the week's capacity | Inventory selected Projects separately, discuss capacity together, save each Project's slice | Weekly focus: Weekly review and commitment |

Run behavioral tests before claiming reliable end-to-end coverage. Connector access limits and missing historical dates can still make a review partial.
